# Phase 8C Control Center audit

## Scope and invariants

Phase 8C changes only the Control Center presentation and its operational boundary.
Phase 4B, 5B, 6B, 6C, and the frozen Phase 7 decision engine are neither retrained nor
modified. Demo data are generated by an isolated in-memory service selected only with
`--demo`; they never open DuckDB, call a live source, write an optimization snapshot, or
enter shadow validation.

## Functional findings fixed

- A saved roster, bank, transfer, availability, or pool-constraint change could leave an
  older recommendation card visible. The UI now invalidates it immediately and verifies
  season, Matchday, market, and prediction identity before restoring a persisted run.
- Concurrent bootstrap requests could resolve out of order and repaint the page with an
  older payload. Monotonic load epochs now discard late responses.
- Repeated clicks could start duplicate refresh, optimization, override, or state requests.
  Client busy guards and a server-side non-blocking refresh lock prevent duplicates.
- A confirmed after-Turn lineup was stored without its immutable shadow identity. It is
  now accepted only for the exact `shadow_snapshot_id`; stale local state is discarded.
- Current-team saves accepted entities outside the market and positional overflow until
  optimization time. The service now rejects unknown entities, duplicates, oversized
  rosters, and positional overflow while still permitting incomplete work-in-progress.
- FORCE INCLUDE of a resolved-OUT player had no warning. It remains legal and explicit,
  but now requires confirmation and returns a backend warning.
- Live refresh returned a single opaque result and unhandled prediction/post-processing
  errors. It now reports actual stages, partial failures, a change summary, retryability,
  and preserves the last valid state. Unexpected HTTP failures receive a request ID while
  full technical details remain in local logs.
- Latest advisor state could be shown for another Matchday. Shadow season/Matchday
  identity is now checked before restoration.

## UX and visual findings fixed

- The player explorer showed every metric at once. It now uses Performance, Risk, Value,
  Minutes, and Strategy column presets, compact filters, status filtering, result counts,
  sticky headers, aligned numbers, and sortable columns.
- Availability editing used a browser prompt. A dedicated dialog now compares source,
  override, and resolved states and supports PLAY, OUT, UNKNOWN, LIMITED, notes, and clear.
- Readiness was distributed across cards and tabs. A persistent global strip now exposes
  season, Matchday, Turn, refresh, market, prediction, rules, scoring, roster credits,
  bank, transfers, and override count with GOOD/WARNING/BLOCKED styling.
- Blank tables and no-season screens looked broken. Intentional empty states now explain
  what is missing, what remains usable, and how demo mode can be launched.
- Recommendation differences required reading long rosters. Cards now emphasize team
  mean/P10/P50/P90, deltas, captain, formation, credits, transfers, IN/OUT, and one primary
  reason; rosters are available in compact disclosure panels.
- KEEP/SWITCH and captain evidence was dense. It now has explicit KEEP, SWITCH, and NO
  ACTION badges, played/option pairs, win probability, full-team values, P10/P90 effects,
  statistical reasons, and formation transitions such as `2-2-1 → 1-3-1`.
- Monitoring mixed unrelated diagnostics and could imply a trend from two rounds. It is
  split into Model Performance, Strategy Behavior, Availability/Data Quality, and Price
  Model, and explicitly withholds trend interpretation below six Matchdays.
- The desktop grid imposed a large minimum width. The application now preserves dense,
  horizontally scrollable tables while adapting navigation, cards, dialogs, and forms at
  laptop, tablet, and mobile breakpoints. Keyboard focus and text/icon status cues were
  added throughout.

## Safe demo catalog

The selector covers exactly A–T: no season, market without predictions, predictions,
mixed availability, overrides, incomplete/valid/budget rosters, zero and variable
transfers, rules/scoring blocks, stale market, failed refresh, completed T1, multiple
switches, captain decision, no legal action, value growth, and empty filters.

Normal mode: `python -m scripts.control_center`

Demo mode: `python -m scripts.control_center --demo`

Specific state: `python -m scripts.control_center --demo --demo-state captain-decision`
